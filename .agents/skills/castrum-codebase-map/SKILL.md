# castrum: Codebase map

Orientation guide. `docs/REPO_MAP.md` is the human navigation doc; AGENTS.md is
the agent-facing map; this skill is the fast index. Read the relevant
`castrum-*` skill for the task you're doing.

## The 5 cross-cutting flows (from REPO_MAP §4)

1. **Constants never drift** — one numeric source: `src/ingress/constants.ts` ←
   `rust/ingress/output.rs` / `ingress_constants.rs`; read, don't hardcode.
2. **Two ingress paths** — fast vs handler wire formats (ADR-0001), never unify.
3. **Addon loading + runtime seam** — `src/runtime/detect.ts` is the only
   `typeof Bun`; addon path resolution in `src/native/loader.ts`.
4. **Runtime adapter** — `src/runtime/index.ts` exposes codec/uuid/env/builtins/
   transport/server/websocket for the public API.
5. **Pooled output buffers** — `src/shared/buffer-pool.ts` (adaptive sizing via
   `AdaptiveEstimate`) on the impurity boundary.

## Dual-binary loader

Baseline `castrum.<platform>-<arch>[-<libc>].node` + SIMD variant
`castrum.linux-x64-v3-gnu.node` (built by `bun run build:v3` →
`scripts/build-v3.sh`). `supportsX8664V3(cpuinfo)` requires ALL of
`avx2, bmi2, fma, sse4_2` — a v3 binary on a non-v3 CPU SIGILLs. Env overrides:
`CASTRUM_NATIVE_LIBRARY_PATH` / `NAPI_RS_NATIVE_LIBRARY_PATH` (a set-but-bad
override throws).

## Test placement rules

New TS tests go in `test/unit/<area>/` mirroring `src/` (see `test/README.md`):
`native/`, `rust-ffi/`, `contract/`, `ingress/`, `shared/`, `integration/`;
property tests in `test/property/`; Node-only integration in
`test/integration/` (`.mjs`, `node --test`). Rust tests live in the SAME
module file (`#[cfg(test)] mod tests`).
